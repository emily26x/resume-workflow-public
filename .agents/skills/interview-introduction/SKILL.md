# Interview Introduction

先读仓库根目录的入口规则、`使用说明/workflow.md`、`使用说明/求职内容工作流协议.md` 和 `简历事实库/_index.md`。JD 与截图只在当前对话中处理，不保存文件、截图、匹配报告或索引。

1. 同岗位已有 final 简历时以它为优先候选，并用 confirmed 事实逐条核验；没有时按求职内容工作流协议直接匹配全部 confirmed 事实。
2. 从 JD 提取 3～5 个核心要求，确定一条有事实支撑的能力主线。
3. 选择两个互补故事。每个故事包含背景、本人角色、具体行动和有证据的结果或产出；没有结果证据时不补造。
4. 用具体的协作、冲突处理和推进事实体现软素质，避免空泛自评。
5. 默认生成约 2.5 分钟的自然口语稿，结构为个人定位、故事一、故事二和经验迁移。材料不足时缩短，不用虚构内容补足时长。
6. 硬性门槛缺口放在介绍稿之外提醒，并区分“没有记录”和“明确不满足”。

结果只在对话中返回。不得创建或更新简历、自我介绍、事实、JD、报告、索引及其他文件。

正式使用只读取 `简历事实库/` 中本人已确认的资料，不读取 `示例资料/` 的虚构事实；事实库为空时先引导用户导入并确认资料。
