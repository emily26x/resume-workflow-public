# resume.md 格式

最小示例：

```markdown
---
status: final
language: zh-CN
target_role: 产品运营
photo: assets/photo.png
sidebar_sections: [个人技能, 技能证书, 荣誉奖项]
source_items:
  - galaxy-feedback-system
  - galaxy-release-loop
  - galaxy-guide
---

# 姓名

> 电话｜邮箱｜[作品集](https://example.com)

一句可选的个人概述。

## 教育背景

### 虚构示例大学｜2020.09–2024.06

- 信息管理与信息系统，本科

## 工作经历

### 虚构示例甲科技 - 产品运营（实习）｜2024.07–2024.12

- **流程优化：** 整理反馈并建立分类规则。
- **协作推进：** 跟进版本问题并完成上线回访。
- **内容优化：** 分析高频问题并重写新手指引。
```

约定：

- 一级标题是姓名，`>` 开头的行是个人信息；可使用多行。
- 二级标题是章节，可以自由选择和排序。
- 三级标题是经历；最后一个 `｜` 或 `|` 后的内容显示为右侧时间。时间应来自事实的独立字段。
- 经历标题中的公司或项目名称与职位、任职性质或项目性质之间使用两侧留空格的半角连字符，例如 `虚构示例甲科技 - 产品运营（实习）`，不使用中点。
- 工作标题应如实反映 `role_title` 和 `employment_type`；项目标题应如实反映 `project_type`。
- 全职（`employment_type: full-time`）在投递简历的经历标题中只显示真实职位，不添加“（全职）”；实习、兼职、合同制、志愿者等其他任职性质仍明确标注。事实库继续保留完整的任职性质字段。
- `sidebar_sections` 指定灰白双栏模板放入侧栏的章节；未配置时使用技能、证书、荣誉、自我评价等常见名称。
- `photo` 可省略，路径相对于当前 Markdown。是否写入照片、城市及链接写法遵循用户偏好。
- `source_items` 记录正文实际采用的 `statement_id`，只用于内部溯源，不渲染到投递正文、HTML、PDF 或 PNG。新简历不保留已退役的选材字段。
- 正文支持段落、无序列表、Markdown 加粗和 HTTP、邮件、电话链接。
- 每段入选工作经历固定 3 条要点，每条聚焦一个主要动作；公共版不设置固定公司组合。
- 不改变现有章节设置和顺序。每个章节内部的带时间经历按时间倒序：进行中优先，其余按结束时间倒序，结束时间相同时按开始时间倒序，无日期条目置底并保持原有顺序。
- `candidate`、待确认标记、匹配分析和内部事实 ID 不能出现在投递版正文中。
