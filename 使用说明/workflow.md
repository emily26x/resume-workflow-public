# 工作流与公共协议

## 1. 建立候选事实

原始材料可以是可提取文字的 PDF、DOCX、图片或直接粘贴的文本。文件放入 `原始材料/`，AI 使用当前环境可用的文档或图片读取能力提取内容，不修改原件。

提取时把经历拆成背景、本人行动、结果或产出、数字锚点、能力信号、时间、真实职位、任职性质和来源。项目另记真实性质。旧简历中的一句话只是证据，不自动视为事实；冲突信息并列保留，并集中询问本人。

## 2. 确认并写入事实库

每段经历拥有稳定 `fact_id`，每条可复用陈述拥有稳定 `statement_id`。状态含义：

- `candidate`：来自材料，尚未得到本人确认。
- `confirmed`：本人已确认，可以用于新输出。
- `retired`：保留追溯，但不再用于新材料。

事实库保留来源。修改 confirmed 事实前再次询问。定制产生的新措辞不能反向覆盖事实，candidate、冲突项和待确认信息不能进入简历、打招呼或自我介绍。

工作事实至少记录真实职位 `role_title` 和 `employment_type`，推荐值为 `full-time`、`internship`、`contract`、`part-time` 或 `volunteer`。项目事实使用 `project_type` 标注 `personal`、`course`、`open-source`、`client` 等真实性质。

## 3. 用户偏好

偏好独立保存在 Git 忽略的 `.resume-workflow/preferences.json`，不属于事实库：

```json
{
  "defaultTemplate": "classic",
  "includePhoto": false,
  "showCity": false,
  "linkStyle": "label"
}
```

首次设置可以逐项选择，也可以跳过。跳过时使用经典黑白、不显示照片、不显示城市、链接显示可读名称。照片和城市仍须来自 confirmed 事实。编辑器首次设置会保存相同偏好；模板立即作用于当前简历，其他偏好供下一次生成 `resume.md` 时读取。

## 4. 临时岗位上下文

JD、JD 图片、岗位分析和修改理由默认只存在于当前对话。针对同一岗位连续生成简历、打招呼和自我介绍时，应复用同一组核心要求和硬性门槛，确保职位、时间、指标和经历性质一致。

选材按[求职内容工作流协议](求职内容工作流协议.md)执行。`resume-tailor` 每次根据 JD 直接匹配全部 confirmed 事实；`job-greeting` 和 `interview-introduction` 可以优先参考同岗位 final 简历，但采用前必须回到事实库核验。先看相关性，再比较指标。硬性缺口必须区分“事实库没有记录”和“已有事实明确不满足”。

## 5. 根据 JD 定制 Markdown

### 岗位档案命名与保存

生成岗位简历前，询问用户并确认目标公司名称和岗位名称；当前对话已明确提供并确认时无需重复询问，不得自行猜测或使用示例名称代替。

正式岗位档案保存在仓库根目录的 `岗位档案/YYYY/YYYY-MM-DD-公司名称-岗位名称/`。`YYYY-MM-DD` 使用首次生成该份 Markdown 当天的本地日期，`YYYY` 取该日期的年份，不使用 JD 发布日期或任职日期。后续修改、确认 final、生成 HTML 或导出均沿用原目录和日期。公司和岗位名称保留用户确认的文字；路径非法字符替换为半角连字符。

目录内使用固定文件名 `resume.md`、`resume.html`、`resume.pdf` 和 `resume.png`。草稿阶段只保存 `resume.md`；用户确认后生成的 HTML 保存到同目录，PDF 和 PNG 也在该目录导出。维护 `岗位档案/YYYY/_index.md`，以公司、岗位和生成日期标识并链接 Markdown；`岗位档案/_index.md` 按年份导航。档案索引同时标注 draft/final 状态。同公司、同岗位、同日的已有档案不得被当作新档案静默覆盖；先确认用户是修改已有档案还是另建版本，另建版本时在目录末尾追加 `-v2`、`-v3` 等未占用后缀。

历史虚构事实和岗位简历统一保存在 `示例资料/`，正式输出不得自动读取。新生成的本人事实放入 `简历事实库/`，正式岗位档案使用上述路径。

将事实拆成背景、行动、结果或产出、数字锚点和能力信号，根据证据使用 PAR、BAR 或 BAO。没有结果证据时只写动作与产出。每条要点须可追溯到 `statement_id`，并在 frontmatter 的 `source_items` 中记录实际采用的 ID；内部 ID 不进入投递正文。

不改变现有章节设置和顺序。每个章节内部的带时间经历按时间倒序排列：进行中优先，其余按结束时间倒序，结束时间相同时按开始时间倒序，无日期条目置底并保持原有顺序。每段入选工作经历固定 3 条要点，每条聚焦一个主要动作；不足 3 条 confirmed 事实时停止生成并说明证据不足。任职性质和项目性质必须如实表达。全职（`employment_type: full-time`）在投递简历的经历标题中只显示真实职位，不添加“（全职）”；实习、兼职、合同制、志愿者等其他任职性质仍明确标注。事实库继续保留完整的任职性质字段。没有对应内容时不创建 AI 实践、荣誉、技能或其他章节。

初稿使用 `status: draft`。本人确认后改为 `status: final`。`resume.md` 只保存最终简历内容；直接匹配、可迁移能力、缺少证据和修改理由留在对话中。

## 6. 打招呼与自我介绍

打招呼从 3～5 个岗位要求出发，直接匹配全部 confirmed 事实，选择 2～3 个最强匹配点。若有同岗位 final 简历，将它作为优先候选范围，但每个匹配点仍须回到事实库核验，不能只压缩简历正文。匹配点尽量来自不同经历，每点只讲一个子项目，使用“JD 能力标签＋动作＋结果或产出＋已有指标”的结构。单位名称只能按需作为事实背书，不能充当能力标签。真实匹配不足时减少编号，不凑数、不补造，正文不超过 250 个中文字符。

打招呼固定以“您好！”开场、以“希望有机会进一步沟通。”结束，中间使用 1～3 个编号匹配点。个人、课程和开源项目须保留真实性质，不能写成任职；指代不清的单位、职位或事实放在正文外待确认。硬性门槛缺口也放在正文外提醒。

自我介绍围绕一条能力主线和两个互补故事，默认约 2.5 分钟。材料不足时减少内容，不凑数、不补造。打招呼和自我介绍都只在对话中返回，不创建文件或更新索引。

## 7. 确认、编辑与导出

用户确认 final Markdown 后再启动编辑器。编辑器切换模板或显示、隐藏源文件中的证件照时，不重新解析 Markdown，也不调用 AI。照片显示状态、修字、加粗、当前模板和各模板排版参数保存在当前浏览器会话，关闭标签页或浏览器会话后可能丢失。

正文字号最低 8.8 pt。95%～96% 页面占用率是建议区间，偏离时提示但不阻断；页面占用率以整张 A4 高度为分母，100% 以内不属于纵向溢出，底部留白不额外限制导出；超过 100%、横向越界或跨页必须停止导出。编辑器与导出共用同一计算规则。PDF 与 PNG 都以当前 HTML 为准。

## 8. 输出边界

| 内容 | 默认保存位置 |
|---|---|
| confirmed 事实 | `简历事实库/` |
| draft / final 简历 | `岗位档案/YYYY/YYYY-MM-DD-公司名称-岗位名称/resume.md` |
| 生成的 HTML 文件 | `resume.md` 同级的 `resume.html` |
| HTML 修字与排版状态 | 当前浏览器会话 |
| 打招呼、自我介绍、JD 分析 | 仅当前对话 |
| PDF / PNG | `resume.md` 同级目录 |

## 9. 索引维护

所有 `_index.md` 按[索引规范](索引规范.md)记录 created、updated、type/index、索引自身状态与 aliases，并提供用途、分类导航及 Related。Source 按需添加。创建或更新内容时同步受影响的各层索引；文件实际生成后才增加链接，索引摘要不能代替正文核验。

## 10. Git 隐私边界

本仓库面向不同使用者公开分发，但每位使用者的真实资料只保存在自己的本地副本中。`原始材料/`、`简历事实库/`、`岗位档案/` 和 `.resume-workflow/` 下的私有内容与本地索引均由 `.gitignore` 排除；公开仓库只保留入口说明、索引模板和虚构示例。

AI 和维护者不得使用 `git add -f` 绕过忽略规则，不得把真实资料、真实岗位 HTML 或导出文件移动到 `示例资料/` 等公开路径。修改 `.gitignore`、准备发布或推送前必须运行 `npm run privacy-check`，分别检查已跟踪文件和暂存区，再运行完整测试。检查器默认阻断未知二进制文件；公开图片只有经过人工复核并锁定哈希后才能放行。自动检查仍无法识别所有形式的个人信息，因此发布前人工复查是最后一道保护。

## 测试阶段的固定示例照片

用户明确表示“测试阶段”或要求使用示例虚拟经历时，使用 `示例资料/完整工作流/facts/` 的虚构人物林知夏，并始终绑定 `示例资料/排版案例/assets/sample-photo.png` 作为证件照。生成示例 `resume.md` 时必须写入相对于该文件的 `photo` 路径；生成 HTML、启动编辑器和导出 PDF/PNG 时默认显示这张照片。此测试约定优先于通用的无照片默认偏好，不能把图片或虚构经历写入本人事实库。图片沿用现有授权说明。
