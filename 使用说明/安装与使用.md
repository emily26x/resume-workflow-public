# 安装与使用

## 在 AI 工具中开始

下载并解压完整仓库，在项目根目录打开工具：

- **Codex**：读取 `AGENTS.md` 和 `.agents/skills/`。
- **Claude Code**：读取 `CLAUDE.md` 和 `.claude/skills/`。
- **OpenCode**：在根目录运行 `opencode`，读取 `AGENTS.md` 并从 `.agents/skills/` 发现四个 Skill；仓库不提供额外的 `.opencode/skills` 或 `opencode.json`。如工具限制了技能访问，请检查该工具的权限设置。
- **WorkBuddy 桌面版**：可从 [Gitee](https://gitee.com/emily26x/resume-workflow-public) 下载仓库完整 ZIP 并解压。在 WorkBuddy 新建本地任务时，把解压后的仓库根目录设为工作目录。`CODEBUDDY.md` 是项目入口，`.codebuddy/skills/` 提供四个 Skill 入口；让 WorkBuddy 先读取项目入口和 `使用说明/workflow.md`。如果任务中没有看到这些 Skill，先检查工作目录是否选在仓库根目录，再到 WorkBuddy 的技能管理界面导入对应 Skill。

四个技能分别负责事实整理和导出（`resume-workflow`）、定制简历（`resume-tailor`）、求职打招呼（`job-greeting`）、面试介绍（`interview-introduction`）。用户直接说自己的需求即可，不必记住技能名。

导入资料和写稿由 AI 完成，无需先启动本地编辑器。首次使用请从根目录 README 的步骤开始。

WorkBuddy 首次试用可先说：“请读取本项目的 `CODEBUDDY.md` 和 `使用说明/workflow.md`，列出四个求职 Skill，然后只用 `示例资料/` 演示一遍。”下载公开仓库不会带上其他使用者的真实简历；自己的资料应留在本机受 Git 忽略的目录内。使用真实资料前，检查 WorkBuddy 当前任务的模型和数据使用设置是否符合自己的隐私要求。

## 安装本地编辑器

排版与导出需要电脑上安装 Node.js 22.13 或更新版本，并允许 WorkBuddy 在本地项目目录运行命令。在项目根目录运行：

```bash
npm install
npm run install-browser
```

安装脚本会先查找已有浏览器，包括系统 Chrome 或 Edge；找到后直接复用，不再下载。没有可用浏览器时才安装 Chromium。可使用 `RESUME_BROWSER_PATH` 指定浏览器位置。在 WorkBuddy 中也可让它执行这两条安装命令；如果应用没有本地命令权限，就在系统终端里运行。

只有已确认并标记 `status: final` 的 Markdown 能进入编辑器。用户在对话中确认后，AI 应检查文案并启动编辑器。手动命令如下，请把路径换为自己的文件位置：

```bash
npm run check -- --input "岗位档案/2026/2026-09-18-公司名称-岗位名称/resume.md"
npm run editor -- --input "岗位档案/2026/2026-09-18-公司名称-岗位名称/resume.md"
```

打开终端显示的完整 HTTP 地址。地址包含本次启动随机生成的会话令牌，只在当前编辑器进程中有效，不要删除地址参数或转发给他人。默认端口是 `4277`；端口占用时增加 `--port 4278`。

## 先试用虚构案例

```bash
npm run check -- --input "示例资料/排版案例/resume-medium.md"
npm run editor -- --input "示例资料/排版案例/resume-medium.md"
```

这些资料仅用于演示，不会进入本人的事实库。

日常修改简历后只需运行 `npm run check -- --input <resume.md>`。`npm test` 包含浏览器测试，仅在修改项目代码、明确要求测试或准备发布时运行；打开编辑器本身不需要启动自动化浏览器，点击导出 PDF/PNG 则需要。

## 文件与保存边界

- `resume.md` 是文案来源；草稿确认前不生成 HTML 或启动编辑器。
- 确认后由 AI 将生成的页面保存为同级 `resume.html`，并启动完整编辑器。当前 `npm run editor` 只启动服务，不自动写入 HTML 文件。
- 编辑器中的修字、加粗和排版仅存在当前浏览器会话，不回写 Markdown、事实库或已有静态 HTML；关闭后可能丢失。
- 点击导出，在 Markdown 同目录生成 `resume.pdf` 和 `resume.png`，再次导出覆盖这两个文件。
- 初次设置偏好保存在 `.resume-workflow/preferences.json`，不属于事实库。可以跳过，默认经典黑白、无照片、不显示城市、链接用可读名称。

## 常见问题

- **找不到事实库？** 根目录“简历事实库”保存本人资料，下载时为空，先让 AI 导入原始材料。
- **为什么要确认？** 从旧简历提取的内容仍可能有歧义，确认前不能用于新输出。
- **为什么打不开编辑器？** 检查是否已安装依赖、文案是否确认并标记 final、命令是否在项目根目录运行。
- **为什么只看到一张简历？** `resume.html` 是静态页面。完整编辑器要运行 `npm run editor -- --input <resume.md>`，并打开终端返回的带 `token` 参数的 HTTP 地址；左侧调节面板只在该地址出现。
- **WorkBuddy 为什么提示删除 Chrome 文件？** macOS 上的系统 Chrome 可能为新启动的浏览器进程创建 `com.google.Chrome.code_sign_clone` 临时副本，并在退出时清理。导出 PDF/PNG 或运行完整浏览器测试时，WorkBuddy 可能拦截这项清理。只有确认目标位于该临时副本目录、而非项目或个人资料目录时，才逐次选择「允许删除」；不要选择「本次会话内始终允许」。路径不同或无法确认时，先拒绝并核对。拒绝不会删除简历，但可能留下临时副本，导出或测试也可能无法完成。
- **导出提示溢出？** 调整字号、间距或切换模板。正文不得小于 8.8 pt，裁切、跨页和溢出会阻止导出。
- **页面占用率不在 95%～96%？** 这是建议，不是阻断条件；以溢出检查为准。
