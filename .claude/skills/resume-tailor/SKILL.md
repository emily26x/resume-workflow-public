# Resume Tailor

先读仓库根目录的入口规则、`使用说明/workflow.md`、`使用说明/求职内容工作流协议.md`、`使用说明/markdown-contract.md` 和 `简历事实库/_index.md`。直接将 JD 与全部 confirmed 事实匹配，只打开实际需要引用的事实正文。

## 处理 JD

JD 仅作为当前对话的临时材料。提取职责、3～5 个核心要求、硬性门槛和加分项，不保存 JD、截图、匹配报告或修改理由，除非用户明确要求。

## 从事实重新选材

1. 每份简历都根据 JD 从全部 confirmed 事实重新选材，不从历史定制简历复制内容，不设置固定公司组合。
2. 按 `使用说明/求职内容工作流协议.md` 的统一优先级匹配事实，不用弱相关的高指标替代强相关经历。
3. 将候选经历理解为背景、行动、结果或产出、数字锚点和能力信号，并检查原始证据。
4. 依据证据完整度使用 PAR、BAR 或 BAO。没有结果证据时，写清动作与产出，不补造结果。
5. 每条要点必须能追溯到 `statement_id`，并将正文实际采用的 ID 记录在 frontmatter 的 `source_items` 中。内部 ID 不进入投递正文，新措辞不能自动回写事实库。

## 生成 resume.md

生成前按 `使用说明/workflow.md` 的岗位档案规则确认公司与岗位；缺少时先询问用户。保存到 `岗位档案/YYYY/YYYY-MM-DD-公司名称-岗位名称/resume.md`，日期取首次生成当天的本地日期，年份与日期一致。修改同一档案沿用原目录，更新 `岗位档案/_index.md`；同名档案的处理遵循工作流规则，不静默覆盖。

- 简历开头固定按“个人信息 → 教育背景 → 工作经历”的顺序排列；个人信息包含姓名、联系方式和可选的个人概述。其他章节放在这三部分之后。
- 经历标题中的公司或项目名称与职位、任职性质或项目性质之间使用两侧留空格的半角连字符，例如“虚构示例甲科技 - 产品运营（实习）”；不使用中点“·”。
- 不改变现有章节设置和章节顺序。每个章节内部的带时间经历都按时间倒序：进行中优先，其余按结束时间倒序，结束时间相同时按开始时间倒序，无日期条目置底并保持原有顺序。时间保留为独立字段，供模板右对齐。
- 每段入选工作经历固定保留 3 条要点，每条只表达一个主要动作。不足 3 条 confirmed 事实时，停止生成并向用户说明证据不足；不得为凑数拆分同一事实或补造内容。
- 任职名称与 `employment_type` 以事实为准。个人项目和练习项目必须标明真实性质，不得包装成正式任职。
- 全职（`employment_type: full-time`）在投递简历标题中只显示真实职位，不添加“（全职）”；实习、兼职、合同制、志愿者等其他任职性质仍明确标注。事实库继续保留完整的 `employment_type`。
- 除前三部分外，其他章节的名称、顺序和有无保持灵活。AI 项目按真实性质进入项目经历或 AI 实践；没有事实时省略相关章节。
- 工作经历和项目经历中，每条要点的开头采用“动作动词＋具体工作对象＋推进方向或产出”的短语式概括，格式为“**概括短语：** 具体行动与结果”。例如：协调科研合作与会议推进、协同构建运营评估指标、统筹跨团队方案落地。此规则适用于每条经历要点，不是每家公司统一写一个概括。
- 概括须准确覆盖本条正文，避免仅用“数据分析”“活动执行”“跨团队协作”等泛化能力标签。根据事实选择“协助”“协同”“负责”“统筹”等动词，不夸大参与程度；推进方向或产出按实际证据表达，不强行补齐。
- 可以加粗关键数字和能力，但不要机械加粗全部 JD 关键词。
- 照片、城市和链接写法遵循 `.resume-workflow/preferences.json`；文件不存在时使用公共默认值。
- 用户明确表示“测试阶段”或要求使用示例虚拟经历时，必须使用虚构人物林知夏，并在示例 `resume.md` 中绑定 `示例资料/排版案例/assets/sample-photo.png`；生成 HTML、启动编辑器和导出 PDF/PNG 时默认显示。不得将示例照片或虚构经历写入本人事实库。
- 格式遵循 `使用说明/markdown-contract.md`。正文只保留最终简历内容。

先把岗位文件保存为 `status: draft`。在对话中展示：

1. 直接匹配；
2. 可迁移能力；
3. 缺少证据，并区分“事实库没有记录”和“已有事实明确不满足”。

用户确认文案后才改为 `status: final`，随后交给 `resume-workflow` 打开编辑器。候选事实、待确认信息和本次新生成的未经确认措辞不得作为事实来源。

正式使用只读取 `简历事实库/` 中本人已确认的资料，不读取 `示例资料/` 的虚构事实；事实库为空时先引导用户导入并确认资料。

创建或更新内容时，按 `使用说明/索引规范.md` 同步维护受影响的各层索引与 updated；created 保持不变。正式岗位档案总索引按年份导航，年度索引列具体简历。交付文件实际生成后才增加对应链接。
