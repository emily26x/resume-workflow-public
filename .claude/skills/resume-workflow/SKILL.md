# Resume Workflow

先读仓库根目录的入口规则、`使用说明/workflow.md` 和 `简历事实库/_index.md`。这个 Skill 负责事实建库与交付；根据 JD 写简历使用 `resume-tailor`。

## 从旧简历建库

1. 接受 `原始材料/` 中可提取文字的 PDF、DOCX、图片、纯文本，或对话中粘贴的内容。
2. 使用当前环境可用的文档或图片读取能力提取原文，不修改或删除原件。
3. 将经历拆成任职时间、真实职位、`employment_type`、背景、本人行动、结果或产出、数字锚点、能力信号和来源。项目另记 `project_type`，不得把个人项目包装成任职经历。
4. 新提取内容一律标记为 `candidate`。集中列出冲突、指代不明和缺少证据的信息，请用户确认。
5. 只有用户明确确认后才改为 `confirmed`，分配稳定 `fact_id` 和 `statement_id`，写入 `简历事实库/` 并更新索引。

旧简历中的营销性措辞不是已确认事实。不得补造数字、结果、任职性质、职位或技能。

## 首次设置

首次建库时允许用户选择默认模板、是否显示照片、是否显示城市和作品链接形式。设置保存在 `.resume-workflow/preferences.json`，不写入事实库。用户可以全部跳过；默认值为：

- 模板：`classic`（经典黑白）
- 照片：不显示
- 城市：不显示
- 链接：使用可读名称，不直接铺开长 URL

照片和城市只有在事实库存在 confirmed 内容且设置允许时才能进入 `resume.md`。用户之后可以修改设置。

测试演示例外：

- 用户明确表示“测试阶段”或要求使用示例虚拟经历时，必须使用虚构人物林知夏，并在示例 `resume.md` 中绑定 `示例资料/排版案例/assets/sample-photo.png`；生成 HTML、启动编辑器和导出 PDF/PNG 时默认显示。不得将示例照片或虚构经历写入本人事实库。

## 确认、编辑与交付

正式档案使用 `使用说明/workflow.md` 规定的 `岗位档案/YYYY/YYYY-MM-DD-公司名称-岗位名称/`。交付时沿用 Markdown 所在目录和首次生成日期，将生成的 HTML 保存为同级 `resume.html`，不另建日期目录；导出文件仍为同级 `resume.pdf`、`resume.png`。现有历史演示路径保持兼容。

只有用户确认并标记为 `status: final` 的 `resume.md` 可以进入编辑器：

```bash
npm run check -- --input <resume.md>
npm run editor -- --input <resume.md>
```

模板切换只改变视觉呈现，保留文字、加粗和链接。各模板分别记住当前简历的排版参数。正文字号不得低于 8.8 pt；95%～96% 页面占用率是建议区间，区间外给出提示。裁切、溢出或跨页是硬错误，必须阻止导出。

HTML 修改只保存在当前浏览器会话，不回写 Markdown 或事实库。用户点击导出后，在 Markdown 同级生成一页 A4 `resume.pdf` 和 2480 × 3508 `resume.png`。

生成 HTML 文件后，必须在对话的最终回复中提供可点击的 HTML 文件地址。使用绝对路径 Markdown 链接，例如 `[HTML 简历](/绝对路径/resume.html)`；不能只告知生成成功或只打开预览。

交付顺序固定为：生成或修改 Markdown 草稿 → 用户确认本版文案 → 标记 final → 生成 HTML 并启动完整编辑器 → 在对话中提供地址。确认前只交付 Markdown，不生成或更新 HTML、不启动编辑器。之前对其他版本的确认或打开编辑器的要求，不自动适用于新生成的 Markdown 文案；用户可在一次回复中确认文案并要求生成 HTML，无须重复确认。编辑器中的修字、加粗、模板切换和排版调整不需要重新确认 Markdown。

进入交付阶段后，应提供包含模板切换、文字编辑、排版微调和导出控件的完整编辑器，并在最终回复中提供 HTTP 地址；静态 HTML 或 PDF 预览不能替代编辑器。

正式使用只读取 `简历事实库/` 中本人已确认的资料，不读取 `示例资料/` 的虚构事实；事实库为空时先引导用户导入并确认资料。

创建或更新内容时，按 `使用说明/索引规范.md` 同步维护受影响的各层索引与 updated；created 保持不变。正式岗位档案总索引按年份导航，年度索引列具体简历。交付文件实际生成后才增加对应链接。
